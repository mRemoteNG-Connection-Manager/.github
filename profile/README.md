# mRemoteNG - Connection Manager with Protocol Tabs and a Config File

## About mRemoteNG

mRemoteNG is a tabbed connection manager for hosts you may reach. mRemoteNG Connection Manager is the list. mRemoteNG Session Tree is the folder tree of those entries. mRemoteNG Protocol Tabs are open sessions (RDP, SSH, VNC, and others you configured). mRemoteNG Remote Console is the live view in a tab. mRemoteNG Config File is the XML-style store of that inventory.

Build mRemoteNG Session Tree with in-scope names only. Put secrets in the store the process allows, not in a chat log. Open one mRemoteNG Remote Console from mRemoteNG Protocol Tabs. Keep mRemoteNG Connection Manager boring. Back up mRemoteNG Config File like any other inventory. This is not a scanner of the internet.

mRemoteNG Connection Manager, mRemoteNG Session Tree, mRemoteNG Protocol Tabs, mRemoteNG Remote Console, and mRemoteNG Config File exist to open allowed remotes from a list you can version.

## Key Features of mRemoteNG

- **Connection manager as the list** – mRemoteNG Connection Manager is every node you bother to name. mRemoteNG Session Tree folders keep them readable. mRemoteNG Config File persists that. mRemoteNG Protocol Tabs open from a node. mRemoteNG Remote Console is that node live.
- **Session tree as folders** – mRemoteNG Session Tree is environment, then host. Boring. mRemoteNG Connection Manager without folders becomes a dump. mRemoteNG Config File should stay small enough to diff. mRemoteNG Protocol Tabs should not be your folder system. mRemoteNG Remote Console is not a place to store notes.
- **Protocol tabs as opens** – mRemoteNG Protocol Tabs are one session each. Close them. mRemoteNG Remote Console in a forgotten tab is a lock out. mRemoteNG Connection Manager still has the definition. mRemoteNG Session Tree still has the path. mRemoteNG Config File still has the node.
- **Config file as inventory** – mRemoteNG Config File is what you back up. It can contain secrets; protect it. mRemoteNG Connection Manager loads it. mRemoteNG Session Tree is inside it. mRemoteNG Protocol Tabs are not. mRemoteNG Remote Console is not.
- **Remote console as the live view** – mRemoteNG Remote Console is the reason the tool exists. Test credentials once. Use mRemoteNG Protocol Tabs to keep two consoles only if you must. Find the host again via mRemoteNG Session Tree. Save via mRemoteNG Config File. Keep mRemoteNG Connection Manager in-scope.

## Quick Start with mRemoteNG

1. **One host** – New mRemoteNG Config File. One node in mRemoteNG Connection Manager. Folder in mRemoteNG Session Tree. Connect. Confirm mRemoteNG Remote Console. Close the tab among mRemoteNG Protocol Tabs.
2. **Save** – Save mRemoteNG Config File to a path you back up. Do not put it on a shared desktop. mRemoteNG Connection Manager should reload it. mRemoteNG Session Tree should look the same. No extra mRemoteNG Protocol Tabs. No idle mRemoteNG Remote Console.
3. **Fill the tree** – Add in-scope hosts to mRemoteNG Session Tree. Same mRemoteNG Config File. Open only the mRemoteNG Remote Console you need. Keep mRemoteNG Protocol Tabs short. Keep mRemoteNG Connection Manager names safe in a screenshot.
4. **Protect secrets** – If the file stores passwords, treat mRemoteNG Config File as a secret. Restrict ACLs. mRemoteNG Connection Manager on a workstation you own. Disconnect mRemoteNG Remote Console. Close mRemoteNG Protocol Tabs. Do not mail the file.
5. **Review** – Delete dead nodes from mRemoteNG Session Tree. Save mRemoteNG Config File. Close leftover mRemoteNG Protocol Tabs. No parked mRemoteNG Remote Console. mRemoteNG Connection Manager should match the estate you still touch.
